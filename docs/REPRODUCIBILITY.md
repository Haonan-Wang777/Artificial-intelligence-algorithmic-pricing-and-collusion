# 可重复性与检查方法

本项目按论文、附录独立实现，并提供用户上传的作者原始代码用于核验。真正上传的27.3 MB复现包完整且正确；本地另有的无关库存旧ZIP曾在初次审计中被混淆，此错误已纠正，详见 [`notes/source_audit.md`](../notes/source_audit.md)。作者代码和未修改的 baseline.exe 按原许可保留于 `vendor/calvano_original`；原程序已在补充现有 Intel OpenMP 运行库搜索路径后成功执行小规模实验。

## 环境与依赖

本次环境使用 Python 3.12.5、Windows 64 位；实际安装的依赖精确版本保存在 [`requirements-lock.txt`](../requirements-lock.txt)。为尽量接近本次环境，使用 Python 3.12.5 创建虚拟环境后运行：

```text
python -m pip install -r requirements-lock.txt
python -m pip install --no-deps -e .
```

[`requirements.txt`](../requirements.txt) 给出兼容版本范围，适用于环境迁移；严格复核本次结果优先使用锁定文件。锁定 Python 依赖仍不意味着不同 CPU、操作系统、BLAS 或 LLVM 版本必然产生逐位一致的结果。每次运行的 `manifest.json` 保存 Python、平台、NumPy、SciPy、Numba 版本，完整配置及源文件哈希，以便检查实际运行环境。

## 随机种子与学习流程

Python 配置中 `seed_start=20261023`，每个情景内第 `i` 个会话（从 `0` 开始）使用 `20261023+i`。不同情景使用相同的种子编号集合，便于参数比较；同一情景内每个会话独立设种子。重试或进程调度不会从某个全局随机流继续取数。

学习内核使用 NumPy/Numba 的 MT19937 随机流。作者 Fortran 原程序使用 RAN2，按会话负索引和固定辅助种子初始化，并为初始状态使用单独的随机流；Python 使用不同的随机流，**不主张与论文使用相同的随机序列**。固定本项目种子保证的是本项目自身的可检查性，不能消除有限样本统计误差。

初始状态随机抽取；初始 Q 值按对手均匀随机定价的折现收益设置；探索概率从 `t=0` 的 `exp(-beta*t)` 开始。各企业先同时选择动作，再用更新前 Q 值计算目标，随后更新。Python 并列最大值选择最低价格；作者原程序随机打破并列。这是两条运行路径的实现差异，应分别记录与比较。收敛窗口检查所有状态上的贪婪策略连续不变，窗口长度与训练上限均由配置明确给出。

## 实际运行和恢复

从项目根目录可先运行集成检查，再运行正式交付配置：

```text
python experiments/run.py --config configs/smoke.json --output results/smoke_check --workers 1
python experiments/run.py --config configs/validated.json --output results/recheck --workers 2
```

`--workers` 控制独立进程数量。每个进程处理完整会话，训练内部没有并行归约；任务按索引记录与汇总，调度顺序不参与种子生成。增加进程数主要改变耗时。应在相同环境下抽查 `--workers 1` 与 `--workers 2` 的同种子结果，而不是假定任意平台均逐位一致。

同一输出目录再次运行时，脚本按运行标识读取已有的逐会话 JSON 和快照，跳过已完成任务。配置或实现变更后使用新的 `--output`，避免将两批实验混合。环境升级后也应选择新目录，保留前一次的 manifest 作为证据。恢复功能目前针对已完成会话；单个会话中断后从该会话的种子重新训练。

## 作者可执行程序的重复运行

原程序使用自己的 RAN2 种子规则，不读取 Python 的 `seed_start`。本机已验证的调用方式可通过 `experiments/run_original.py --help` 查看；`--runtime-path` 指向本地可用 Intel OpenMP 运行库目录。本机已有 MATLAB 安装为此提供了路径，不将该商业软件运行库复制到项目。

作者运行目录的 `execution.json` 记录 exe、输入文件、运行库和输出文件 SHA256，程序返回码及命令参数；`InfoExperiment_1.txt` 保存逐会话策略和最终状态。原程序记录的收敛时间扣除了稳定窗口且以 25,000 期为单位，与 Python 的含稳定窗口总步数不能直接同名比较。应比较完整输入、策略和口径一致的统计量。

## 原始运行记录与派生结果

输出目录按情景组织；`baseline/session_00000.json` 等文件是逐会话原始诊断记录，`session_00000.npz` 是同一会话的策略与历史快照。没有额外名为 `raw/` 的必要目录。

| 记录 | 用途 |
|---|---|
| `manifest.json` | 运行命令、配置、平台和核心依赖版本、源码 SHA256、运行标识 |
| `<scenario>/session_*.json` | 会话编号、种子、训练步数、是否收敛、终态、循环和均衡诊断、快照名、耗时 |
| `<scenario>/session_*.npz` | 全状态贪婪策略、终态、训练区间收益；配置指定的前若干会话另外保存 Q 矩阵 |
| `summary.json` | 从逐会话记录汇总的结果 |
| `tables/sessions.csv` | 可用表格软件检查的逐会话数据 |
| `tables/paper_comparison.csv` | 论文印刷数值、复现值、绝对误差与相对误差 |
| `figures/` | 由保存的数据生成的图像 |

`converged=false` 表示在配置训练上限内未满足停止准则，终止策略的诊断值可供检查，但不纳入主要收敛结果均值。应同时报告会话总数、收敛数与截尾数，不能把被截尾会话当作收敛。

## 导师核查步骤

1. 核对配置与论文的经济参数、学习参数、收敛窗口、样本数及训练上限。降低会话数量或缩短上限属于实验规模调整，不能称为论文完整规模复现。
2. 核对 `manifest.json` 与本地实际版本、源码哈希；检查 JSON 会话数与配置目标数是否相同，种子是否按规则连续。
3. 从 JSON 抽取若干会话，与同名 NPZ 的终态和策略比对；按相同配置和种子重新运行，比较策略数组、训练步数和诊断数值。
4. 从逐会话记录重新汇总，而不把图片当作原始数据。先核对均值、标准差、收敛比例，再核对论文比较表中的误差计算。
5. 检查策略循环是否逐相位等权、不同会话是否等权；检查脉冲响应是否关闭学习和探索，并按周期各相位平均。
6. 比较随机结果时区分抽样误差与实现偏差。跨环境出现近似并列 Q 值时，浮点微小差异可能改变贪婪动作并放大为路径差异；记录环境并比较统计分布，不能据此自动判定模型设定正确或错误。

耗时、时间戳和压缩文件的容器字节无需逐位一致；策略、种子、训练步数、收敛状态和统计量才是重跑检查的对象。论文仅印刷到有限小数位，原文四舍五入误差与抽样误差也应分别注明。
